### 3. 展示控制 & 自定义字段

**展示控制：** 全局设置 + 单词级覆盖
```sql
CREATE TABLE display_settings (
  field_id TEXT PRIMARY KEY REFERENCES field_definitions(id),
  visible INTEGER NOT NULL DEFAULT 1,
  display_order INTEGER NOT NULL
);
CREATE TABLE word_display_overrides (
  word_id TEXT NOT NULL REFERENCES words(id),
  field_id TEXT NOT NULL REFERENCES field_definitions(id),
  visible INTEGER,
  PRIMARY KEY (word_id, field_id)
);
```

**自定义字段：** 放开 `field_definitions` 的写入权限（当前已有表结构支持，只需加 UI）

**不影响 v0.1：** 纯新增表和 UI，零改动 v0.1 数据逻辑。

## 三、字段系统设计

### 3.1 核心理念：字段跟着数据走

**设计决策：** 不需要预先创建字段类型、不需要字段模板配置、不需要字段映射规则。

字段是添加词汇时从词典自然带入的：

用户搜索词汇 → 词典返回字段列表 → 用户勾选想要的字段 → 字段随词汇进入词库

模板是「静默的、潜在的」——不是用户可见可点击的功能，而是自然发生在添加流程里的行为。词典返回什么字段，用户就看到什么字段，勾选后直接进词库。



### 3.2 字段数据结构

**词汇条目：**

interface Vocabulary {
  id: string
  word: string
  createdAt: number
  fields: Field[]  // 数组，不是键值对
 }

 interface Field {
  id: string
  key: string    // 字段类型标识（从词典带过来的，用于归类）
  label: string    // 显示名（从词典带过来的）
  value: string    // 实际内容
  source: string   // 来源（'local' / 'online' / 'manual'）
  order: number    // 排序位置，支持拖拽调整
 }

**关键设计点：**

•      **fields** **是数组，不是键值对** —— 同一个 key 可以出现多次。例如用户同时要本地和在线的音标，就是两条 phonetic 字段。

•      **字段记录** **source** —— 标记它从哪来，方便追溯。如果某个词典数据有误，可按来源批量清理。

•      **字段有** **order** **属性** —— 按添加顺序递增，用户可在详情页拖拽调整展示顺序。



### 3.3 添加流程（静默模板）

用户读文章遇到生词 → 在软件中搜索
  → 内置搜索引擎展示这个词，包括词的各种字段
  → 所有字段默认全选（勾选框，默认为全选）
  → 用户取消勾选不需要的字段
  → 点击「添加到词库」
  → 词带着经过用户选择的字段进入词库

无需任何字段映射、模板配置、预先创建字段的步骤。字段从词典流到词库，中间只过了用户的手。



### 3.4 词汇详情页

所有字段操作在词汇详情页的上下文中完成，不需要独立的字段管理页面：



| 操作         | 位置                       |
| ------------ | -------------------------- |
| 查看字段     | 词汇详情页                 |
| 编辑字段值   | 词汇详情页内联编辑         |
| 删除字段     | 词汇详情页，点删除按钮     |
| 调整字段顺序 | 词汇详情页，拖拽排序       |
| 追加新字段   | 词汇详情页，点「添加字段」 |



### 3.5 手动添加词汇

非词典来源的词汇，提供空白状态：

•      用户输入一个词，系统未找到词典结果

•      展示空白状态，提供两个入口：

–     **手动添加字段：** 添加一个空的字段（用户自己填字段名和值）

–     **搜索词典自动填充：** 走搜索流程，从词典获取字段



### 3.6 对 M2 模块的影响

M2 不作为独立的「字段管理系统」，而是作为词汇条目的附属能力：

•      字段作为词汇条目的 fields 数组存在

•      字段操作在词汇详情页完成

•      不需要独立的字段管理页面、字段类型配置页、模板管理页

•      M2 的开发量大幅降低，核心只需实现字段的增删改查和排序





## 四、搜索功能与字段系统的协作流程

### 4.1 完整用户流程

1. 用户读文章遇到生词 "ephemeral"
2. 在 Lexiloom 中搜索
3. 系统同时查询本地词典和在线词典（如开关开启）
4. 本地结果先返回，先展示
5. 在线结果返回后，追加到下方
6. 用户浏览结果，点「选字段」
7. 弹出统一字段选择面板，所有来源的字段按 key 分组展示，默认全选
8. 用户取消勾选不需要的字段（如不要英文释义）
9. 点击「添加到词库」
10. 词汇 "ephemeral" 带着选中的字段进入词库
11. 用户可在词汇详情页编辑、删除、排序字段
