# v0.2 词典字段系统设计

> 本文档为 Lexiloom v0.2 的词典增强功能设计规格。
> 关联: `v0.2-dictionary-enhancement.md`（后续规划）、`v0.2-ideas.md`（长期方向）

---

## 一、概述

### 1.1 目标

在 v0.1 的基础上实现：

1. **ECDICT 集成**（英→中离线词典，提供音标、中文释义、英文释义、词形变化）
2. **WordNet 集成**（英英离线词典，提供按词义拆分的英文释义、同义词、例句）
3. **两阶段搜索交互**（模糊单词匹配 → 单击展开详情卡片）
4. **层级字段模板**（释义为主层级，中文/英文释义分别编号，同义词/例句为子层级）
5. **多源字段合并入库**（ECDICT 和 WordNet 的字段合并到同一个词条）
6. **词库内层级字段展示**（保持添加时的层级结构）

**不在当前 v0.2 范围：** Free Dictionary API（在线）、CC-CEDICT 优化、多词义体系。

### 1.2 数据源

| 数据源 | 类型 | 提供字段 |
|--------|------|---------|
| ECDICT | 本地 SQLite（npm 包） | 音标、中文释义（多条）、英文释义（多条）、词形变化 |
| WordNet | 本地 SQLite（从 wordnet-db 构建） | 英文释义（按 synset）、同义词、例句 |
| Free Dictionary API | ⏳ 后续 | — |
| CC-CEDICT | 已有，不动 | — |

### 1.3 搜索路由

```
用户输入
  ├─ 包含 CJK 字符 → 只查 CC-CEDICT（已有，不动）
  └─ 纯英文 → 查 ECDICT + WordNet
```

> 当前 v0.2 实现纯英文搜索路由，ECDICT + WordNet 同时查询。

## 二、搜索交互

### 2.1 两阶段搜索

```
阶段一：用户输入 → 模糊匹配单词名 → 下拉单词建议列表
  │
  │  [ ephemeral               ▼]
  │  ──────────────────────────────
  │    ephemeral
  │    ephemerality
  │    ephemerally
  │
  └── 用户单击一个单词
       │
       阶段二：收起下拉，在下方独立区域展示详情卡片
       
       ┌─ 搜索详情 ──────────────────────┐
       │                                 │
       │ ┌─ ECDICT ────────────────────┐ │
       │ │ [卡片内容—见第三章模板]      │ │
       │ │              [添加到词库]   │ │
       │ └────────────────────────────┘ │
       │ ┌─ WordNet（后续）───────────┐ │
       │ │ [卡片内容]                 │ │
       │ │              [添加到词库]   │ │
       │ └────────────────────────────┘ │
       └─────────────────────────────────┘
```

### 2.2 阶段一：单词建议列表

- 搜索框输入时，300ms 防抖后触发模糊查询
- 查询 ECDICT 的 lemma 索引，返回匹配的单词名
- 显示纯单词列表（无详情），最多 20 条
- 支持键盘导航（↑↓ 选择，Enter 确定）

### 2.3 阶段二：详情卡片

- 用户单击单词后，下拉列表收起
- 搜索框下方出现独立区域，展示该单词的详情卡片
- 每个数据源一张独立卡片，各自有「添加到词库」按钮
- 卡片初始加载时展示骨架屏

## 三、卡片模板

### 3.1 模板结构

```
单词名

[ ] 音标  <phonetic>

[ ] 中文释义① <value> [POS]
[ ] 中文释义② <value> [POS]
...

[ ] 英文释义① <value> [POS]
    [ ] 近义词  <synonyms>
    [ ] 例句
        [ ] <example 1>
        [ ] <example 2>
[ ] 英文释义② <value> [POS]
    [ ] 近义词  <synonyms>
    [ ] 例句
        [ ] <example 1>
...

[ ] 词形变化
    [ ] 过去式: observed
    [ ] 过去分词: observed
    [ ] 现在分词: observing
    [ ] 第三人称单数: observes

              [添加到词库]
```

### 3.2 展示规则

| 字段 | 来源 | 展示条件 |
|------|------|---------|
| 音标 | ECDICT.phonetic | 有则展示 |
| 中文释义 | ECDICT.translation（按 `\n` 分行，每行内再按逗号拆分） | 有则展示 |
| 英文释义 | ECDICT.definition（按 `\n` 分行） / WordNet.gloss（每个 synset 一条） | 有则展示 |
| 近义词 | WordNet.synset.words（排除搜索词本身） | 有则展示 |
| 例句 | WordNet.gloss 中的引号部分 | 有则展示 |
| 词形变化 | ECDICT.exchange（解析为可读标签） | 有则展示 |

### 3.3 编号规则

- 中文释义、英文释义各自独立编号（中文释义①、中文释义②……）
- 编号仅在同类型释义有多个时递增，只有一个时仍标①
- 不同来源的释义在卡片内各自排号，入库后合并统一排号

### 3.4 默认勾选

- 所有字段默认勾选（包括词形变化的各个子条目）
- 父级（释义）勾选 → 自动勾选所有子级（近义词、例句）
- 取消父级 → 子级全部取消
- 单独取消子级 → 父级保持勾选（子级独立控制）

### 3.5 标记推导

- 中文释义的词性标签：从 ECDICT 的 translation 行首提取（如 `vt.`、`vi.`、`n.`、`a.`）
- 英文释义的词性标签：从 ECDICT 的 definition 行首提取（如 `v.`、`n.`、`s.`、`adj.`）
- 词性标签只用于展示，不作为独立字段存储

### 3.6 ECDICT 数据解析规则

```
translation 字段：
  "vt. 觉察到, 遵守, 注意到, 庆祝\nvi. 注意, 评论"
  → 先按 \n 拆分，每行一条 POS 组
  → 行首 "vt." / "vi." / "n." 等提取为 POS 标签
  → 同一行内按逗号拆分，每条为独立的中文释义
  → 结果：4 条 vt. 中文释义 + 2 条 vi. 中文释义

definition 字段：
  "v. watch attentively\nv. behave as expected..."
  → 按 \n 拆分，每行一条英文释义
  → 行首 "v." / "n." / "s." 等提取为 POS 标签

exchange 字段：
  "d:observed/p:observed/i:observing/3:observes"
  → 按 "/" 拆分，每条为：「前缀:值」
  → 前缀映射为可读标签：
    d: = 过去式   p: = 过去分词
    i: = 现在分词 3: = 第三人称单数
    s: = 复数    f: = 比较级
    0: = 原型    1: = 过去式(美式)
  → 展示格式："过去式: observed"
  → 每条作为词形变化的子条目（可独立勾选）
```

## 四、WordNet SQLite 构建

### 4.1 数据来源

- 来源：`wordnet-db` npm 包（已安装），提供 Princeton WordNet 3.1 原生数据文件
- 文件：`index.noun / index.verb / index.adj / index.adv` + `data.noun / data.verb / data.adj / data.adv`
- 总大小：~34MB

### 4.2 构建脚本

新建 `scripts/parse-wordnet.mjs`，流程如下：

1. 读取 `index.{pos}` 文件，建立 `word → synset_offset[]` 映射
2. 读取 `data.{pos}` 文件，提取每个 synset 的：
   - 定义（gloss，`|` 后的部分）
   - 例句（从 gloss 中用引号提取）
   - 同组词（ss_type 后的 words）
3. 写入目标 SQLite 文件 `public/dictionaries/wordnet.db`

### 4.3 目标 SQLite Schema

```sql
CREATE TABLE wn_words (
  lemma TEXT NOT NULL,
  pos TEXT NOT NULL,
  synset_offset INTEGER NOT NULL
);
CREATE INDEX idx_wn_word ON wn_words(lemma);

CREATE TABLE wn_synsets (
  synset_offset INTEGER PRIMARY KEY,
  pos TEXT NOT NULL,
  definition TEXT NOT NULL,
  examples TEXT,      -- \n 分隔的例句
  words TEXT          -- \n 分隔的同组词
);
```

### 4.4 查询流程

```
搜索 "observe" →
  SELECT synset_offset FROM wn_words WHERE lemma = 'observe'
  → 得到 9 个 synset_offset
  → 去 wn_synsets 查每个 offset 的定义/例句/同组词
  → 每个 synset 转为一条英文释义（含同义词、例句）
```

### 4.5 WordNetProvider 接口

```typescript

  readonly name = 'wordnet'

  async searchLemmas(query: string): Promise<string[]> {
    // 模糊匹配单词名（用于阶段一下拉）
  }

  async lookup(word: string): Promise<DictionaryEntry[]> {
    // 精确查单词的所有 synset
    // 每个 synset 返回一条 DictionaryEntry

```

### 4.6 与 ECDICT 的协作

| 维度 | ECDICT | WordNet |
|------|--------|---------|
| 阶段一（单词列表） | 模糊匹配 lemma | 模糊匹配 lemma |
| 阶段二（详情） | 音标、中文释义、英文释义、词形变化 | 英文释义（按义项拆分）、同义词、例句 |
| 展示关系 | 同一张卡片内的字段 | 各自独立卡片，同一模板 |

- 两个卡片分开展示，各自有「添加到词库」按钮
- 点击任一卡片添加按钮，字段合并到同一词条

## 六、字段数据模型

### 4.1 field_values 表变更

```sql
-- v0.1 当前
CREATE TABLE field_values (
  id TEXT PRIMARY KEY,
  word_id TEXT NOT NULL REFERENCES words(id) ON DELETE CASCADE,
  field_id TEXT NOT NULL REFERENCES field_definitions(id) ON DELETE CASCADE,
  value TEXT,
  source TEXT NOT NULL DEFAULT 'user',
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  UNIQUE(word_id, field_id)
);

-- v0.2 改后
CREATE TABLE field_values (
  id TEXT PRIMARY KEY,
  word_id TEXT NOT NULL REFERENCES words(id) ON DELETE CASCADE,
  field_id TEXT NOT NULL REFERENCES field_definitions(id),
  value TEXT,
  source TEXT NOT NULL DEFAULT 'user',
  display_order INTEGER NOT NULL DEFAULT 0,
  parent_id TEXT REFERENCES field_values(id) ON DELETE SET NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

**变更说明：**

| 变更 | 原因 |
|------|------|
| 移除 `UNIQUE(word_id, field_id)` | 允许多条同类型字段（多条英文释义） |
| 新增 `parent_id` | 支持父子层级（释义→近义词、例句） |
| 新增 `display_order` | 同级排序 |
| `field_definitions` 未变 | 字段类型体系保持不变 |

## 七、添加合并逻辑

### 5.1 合并规则

- 用户分别从 ECDICT 卡片 / WordNet 卡片点击「添加到词库」
- 如果词库中已存在该 lemma → 合并新增字段到已有词条
- 如果不存在 → 创建新词条
- 合并时依据 `lemma`（小写）去重

### 5.2 去重策略

- 相同 `field_id` + `value` 的字段视为重复，跳过
- 相同 `field_id` + 不同 `value` 的字段均保留（多条英文释义）

### 5.3 编号重新排定

- 入库后，所有字段按类型分组重新编号：中文释义①~ⓝ、英文释义①~ⓝ
- 编号依据 `display_order` 排序
