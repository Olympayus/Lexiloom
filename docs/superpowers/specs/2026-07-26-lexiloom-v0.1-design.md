# Lexiloom v0.1 设计文档

> 日期: 2026-07-26
> 项目: Lexiloom — Personal Vocabulary Workspace

---

## 1. 产品定位

Lexiloom 不是传统背单词软件。它是一个**以长期积累为核心的个人化英语词汇知识库**——用户收集现实生活中遇到的单词，逐渐补充理解，最终形成属于自己的词汇网络。

v0.1 验证最核心的产品循环：

```
打开软件 → 搜索词典 → 发现单词 → 选择字段 → 保存到词库 → 关闭
                                                        ↓
                                                  重新打开 → 单词还在
```

---

## 2. 核心设计原则

| # | 原则 | 含义 |
|---|------|------|
| 1 | **统一字段模型** | 所有单词信息（释义、词性、例句、笔记……）都是"字段"，没有"核心字段 vs 自定义字段"的区分。系统不搞特例。 |
| 2 | **词典数据永不污染用户数据** | CC-CEDICT 原始数据存放在独立表，用户修改的只是 `field_values` 副本。后续 v0.2 提供一键恢复。 |
| 3 | **允许数据不完整** | 一个单词可以只有英文 + 中文释义。不需要填满所有字段才允许保存。 |
| 4 | **本地优先** | 所有数据存本地 SQLite，离线可用。网络服务是后续增强，不是核心依赖。 |
| 5 | **前端即一切** | 数据库操作从 JS 通过 `tauri-plugin-sql` 直接完成，Rust 层最小化。一个人开发迭代快。 |

## 3. 核心数据模型

### 3.1 words — 单词身份（固定结构）

```sql
CREATE TABLE words (
    id TEXT PRIMARY KEY,
    lemma TEXT NOT NULL,              -- "implement"
    normalized_lemma TEXT NOT NULL,   -- "implement" (小写/去标点，用于排序和搜索)
    language TEXT NOT NULL DEFAULT 'en',
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

`normalized_lemma` 字段是为了后续排序（按字母）、首字母分组等功能能稳定工作，不依赖用户输入的格式。

### 3.2 field_definitions — 字段定义

v0.1 只有 7 个内置字段，不支持用户创建自定义字段（v0.2 再加）。

```sql
CREATE TABLE field_definitions (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,               -- "中文释义"
    key TEXT NOT NULL UNIQUE,          -- "chinese_definition" (程序内标识)
    field_type TEXT NOT NULL DEFAULT 'text',  -- 'text' | 'multiline'
    display_order INTEGER NOT NULL DEFAULT 0,
    created_at INTEGER NOT NULL
);
```

| `key` | `name` | 初始来源 |
|-------|--------|---------|
| `chinese_definition` | 中文释义 | CC-CEDICT |
| `english_definition` | 英文释义 | 用户/后续词典 |
| `part_of_speech` | 词性 | 用户 |
| `derivatives` | 派生词 | 用户 |
| `synonyms` | 近义词 | 用户 |
| `example_sentence` | 例句 | 用户 |
| `usage_scenario` | 使用场景 | 用户 |

### 3.3 field_values — 字段值

```sql
CREATE TABLE field_values (
    id TEXT PRIMARY KEY,
    word_id TEXT NOT NULL REFERENCES words(id) ON DELETE CASCADE,
    field_id TEXT NOT NULL REFERENCES field_definitions(id) ON DELETE CASCADE,
    value TEXT,
    source TEXT NOT NULL DEFAULT 'user',  -- 'cc-cedict' | 'wordnet' | 'user'
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    UNIQUE(word_id, field_id)
);
```

关键设计：
- `UNIQUE(word_id, field_id)` — 每个单词在每个字段下最多一个值
- `source` — 标记数据来源，用户改过后改为 `user`
- 词典数据在独立的 `dictionary_entries` 表，不在 `field_values` 里直接存词典原始数据

### 3.4 词典数据表（独立于用户数据）

```sql
CREATE TABLE dictionary_entries (
    id TEXT PRIMARY KEY,
    word TEXT NOT NULL,
    normalized_word TEXT NOT NULL,
    source TEXT NOT NULL,              -- 'cc-cedict'
    raw_data TEXT NOT NULL,            -- JSON 全文
    created_at INTEGER NOT NULL
);

CREATE TABLE dictionary_fields (
    id TEXT PRIMARY KEY,
    entry_id TEXT NOT NULL REFERENCES dictionary_entries(id) ON DELETE CASCADE,
    field_key TEXT NOT NULL,             -- 对应 field_definitions.key
    field_value TEXT NOT NULL
);
```

`dictionary_fields` 用于搜索索引（`LIKE` 查询），`raw_data` 保留词典 JSON 供后续 v0.2 "重置为词典数据"功能使用。

> 注意：CC-CEDICT 原始数据包含拼音信息，但 Lexiloom 在解析时**直接丢弃拼音**，不存储、不索引、不出现在任何代码路径中。`raw_data` 在入库前也会清理掉拼音字段。

## 4. 搜索与词典系统

### 4.1 两个搜索入口

| | 顶部大搜索框 | 词库内小搜索框 |
|---|---|---|
| 目标 | 搜索 CC-CEDICT 词典 → 发现并添加新单词 | 在已有词汇库中筛选 |
| 数据源 | `dictionary_fields` 表 | `words` + `field_values` 表 |
| 结果 | 未保存的词典条目，每项带"添加"按钮 | 已保存的单词，点入查看详情 |
| 搜索范围 | 英文 lemma + 中文释义 | 英文 lemma + 所有 field_values 内容 |
| 空状态 | "在词典中搜索新单词" | 显示全部词库 |

### 4.2 搜索实现

v0.1 使用 SQLite `LIKE` 查询：

```sql
-- 搜索词典
SELECT de.*, df.field_key, df.field_value
FROM dictionary_entries de
JOIN dictionary_fields df ON df.entry_id = de.id
WHERE de.word LIKE '%' || ? || '%'
   OR df.field_value LIKE '%' || ? || '%'
LIMIT 30;

-- 搜索词库
SELECT w.*
FROM words w
WHERE w.lemma LIKE '%' || ? || '%'
UNION
SELECT w.*
FROM words w
JOIN field_values fv ON fv.word_id = w.id
WHERE fv.value LIKE '%' || ? || '%'
ORDER BY updated_at DESC;
```

后续数据量增大后可升级为 FTS5，只需改 `lib/search.ts` 的内部实现，对外接口不变。

### 4.3 词典 Provider 接口（预留扩展）

```typescript
interface DictionaryProvider {
  name: string
  lookup(word: string): Promise<DictionaryResult[]>
}

interface DictionaryResult {
  word: string
  fields: { key: string; value: string }[]
  source: string
}
```

v0.1 只有 `CcCedictProvider`，后续加 `OnlineProvider` 只需实现该接口，结果在前端合并。

## 6. 技术架构

### 6.1 技术栈

| 层 | 技术 | 选择理由 |
|---|------|---------|
| Desktop 壳 | Tauri 2 | 本地优先，打包体积小，跨平台 |
| 前端 | React + TypeScript | 开发效率高，生态成熟 |
| 构建 | Vite | 速度快，Tauri 官方推荐 |
| 样式 | Tailwind CSS | 实用优先，不搞复杂抽象 |
| 数据库访问 | **tauri-plugin-sql** | JS 直连 SQLite，不写 Rust CRUD |
| 状态管理 | Zustand | 极小（1KB），无样板代码 |
| 数据校验 | Zod | TypeScript 原生，schema 即类型 |
| 包管理 | pnpm | 速度快，磁盘效率高 |
| 词典 | CC-CEDICT (SQLite) | 开源，中英双语，格式稳定 |

### 6.2 为什么不用 Rust 做数据库层

单人开发场景下，每加一个查询就要写 TypeScript + Rust Command + Rust SQL 三处代码，严重拖慢迭代速度。`tauri-plugin-sql` 让前端直接操作 SQLite，v0.1 所有数据逻辑在 TypeScript 层完成。

**Rust 只做**系统级功能：词典文件加载（把 CC-CEDICT 数据库路径暴露给前端），以及未来需要的文件系统操作（导入/导出）、音频播放等。

### 6.3 数据流

```
React 组件
  │
  ├──→ tauri-plugin-sql ──→ SQLite (words, field_values, ...)
  │       (全部 CRUD)
  │
  ├──→ Zustand store ──→ UI 状态缓存
  │
  └──→ tauri invoke() ──→ Rust (仅系统级操作)
                              └──→ CC-CEDICT 词典文件路径
                                      (由 Rust 打包进资源)
```

## 9. 视觉方向

### 品牌语言：The Loom（织机）
### 布局结构：Atelier（工坊）

> Lexiloom 的视觉不是冷淡的极简黑白灰，而是有温度的中性色——像天然纤维织物的质感。实际 UI 配色、字号、间距由前端实现时通过 Tailwind 的 design tokens 统一管理。

### 9.1 品牌色彩

| 角色 | 色值 | 感觉 |
|------|------|------|
| 背景/画布 | `#F6F4EF` 亚麻白 | 柔软、温暖、不刺眼 |
| 表面/卡片 | `#FFFFFF` 白 | 干净的层级感 |
| 文字主色 | `#1C1814` 深墨棕 | 比纯黑柔和 |
| 文字辅色 | `#7A7368` 羊毛灰 | 辅助信息 |
| 品牌色（线色） | `#4A6FA5` 靛蓝 | 安静、专注、有手工艺感 |
| 高亮/强调 | `#C17A4E` 陶土橙 | 暖色点缀，用于搜索高亮等 |

### 9.2 视觉语言

**单词 = 线**：每个单词在列表中，左侧有一条竖线。线初始为浅灰色（`#D9D4CE`）。当用户为该单词填写了至少一个自定义内容（笔记/例句等），线切换为品牌色（靛蓝）——表示这个词正在被"编织"进用户的词汇网络。

**字段 = 织线纹理**：所有字段均匀排列，不做层级嵌套。空字段用虚线边框表示"待补充"，用户填入内容后虚线变实线。

**来源区分**：词典自动填充的内容用浅暖底色块 + 来源标签标注。用户自己写的内容为纯白底 + 正常边框。用户修改后底色块消失，从视觉上区分"来自词典"和"来自自己"。

### 9.3 布局结构

首页采用双栏工坊式布局：
- 左栏：词库列表（可筛选搜索），每条词卡左侧有"线"标记
- 右栏：当前选中单词的工作台，字段按设置排列
- 顶部：始终可见的大搜索框，作为"原材料入口"

右侧工作台是核心操作区域，编辑不需要跳转页面。在较小窗口或首次使用时回退为全屏列表 + 跳转详情页。
