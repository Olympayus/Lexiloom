## 2. Bug 修复

### 2.1 `CcCedictProvider._hydrate` 丢失 word 数据

**问题：** `_hydrate()` 返回的 `DictionaryEntry` 中 `word` 和 `normalizedWord` 始终为空字符串。SELECT 只查了 `id`，没有取 `word` 和 `normalized_word`。

**方案：** 修改 `_hydrate` 的查询和返回值构造。

```typescript
// 改前
const cached = await db.select<{ id: string }[]>(...)
// 改后
const cached = await db.select<{ id: string; word: string; normalized_word: string }[]>(
  `SELECT id, word, normalized_word FROM dictionary_entries WHERE ...`
)

// 改后返回
result.push({
  word: row.word,
  normalizedWord: row.normalized_word,
  source: 'cc-cedict',
  fields: ...
})
```

**改动范围：** `src/providers/cc-cedict.ts` — 仅 `_hydrate` 方法

**影响：** 直接影响搜索结果显示，也影响 `/add` 页面接收 lemma 参数的方式（当前 `DictSearchResult` 传 `entry.word` 时是空字符串，依赖 `entry.fields[0]?.value` 兜底）。

**连带修复：** 检查 `DictSearchResult` 中 `entry.word` 的使用，改为直接从修复后的数据源获取。

### 2.2 WordList 未传递 preview 数据给 WordCard

**问题：** `WordCard` 定义了 `chineseDefinition` 和 `partOfSpeech` 属性，但 `WordList` 从未传入这两个值。左侧词库列表只显示 lemma，不显示释义片段。

**方案：** 在 `db/words.ts` 中新增 `getWordsWithPreviews()` 方法，通过一次 `LEFT JOIN` 批量查询关键字段（chinese_definition, part_of_speech）的最新值：

```sql
SELECT w.*,
       MAX(CASE WHEN fv.field_id = ?1 THEN fv.value END) as chinese_definition,
       MAX(CASE WHEN fv.field_id = ?2 THEN fv.value END) as part_of_speech
FROM words w
LEFT JOIN field_values fv ON fv.word_id = w.id
GROUP BY w.id
ORDER BY w.updated_at DESC
```

其中 `?1` 和 `?2` 是 field_definitions 表中的对应 id（在查询前查一次即可）。

**改动范围：**
- `src/db/words.ts` — 新增 `getWordsWithPreviews()`
- `src/stores/wordStore.ts` — `loadWords` 改为调用新方法
- `src/types/word.ts` — 新增 `WordWithPreview` 类型
- `src/components/layout/WordList.tsx` — 传入 preview 属性
- `src/components/word/WordCard.tsx` — 保持现有 props 不变

**注意：** 不改变 `Word` 接口的定义，`WordWithPreview` 扩展但不替代它。

## 3. 功能补全

### 3.1 词库内搜索覆盖 field_values 内容

**问题：** 设计文档要求词库内搜索范围包含所有字段内容，但当前 `WordList` 的搜索仅在客户端按 `lemma` 做 `Array.filter()`。`lib/search.ts` 已经写好了完整的 `vocabularySearch()`（搜索 lemma + field_values），但未被调用。

**方案：** WordList 的搜索逻辑改为异步调用 `vocabularySearch()`。

```
改前：客户端 words.filter(w => w.lemma.includes(query))
改后：vocabularySearch(query) → 返回匹配的 Word[] → 渲染

保留空查询行为一致（返回全部单词，按 updated_at 降序）
```

**伪代码思维：**
```typescript
// WordList.tsx
const [filtered, setFiltered] = useState<Word[]>([])
const [searching, setSearching] = useState(false)

useEffect(() => {
  if (!filter.trim()) { setFiltered(words); return }
  setSearching(true)
  vocabularySearch(filter).then(setFiltered).finally(() => setSearching(false))
}, [filter, words])
```

**注意性能：** 500+ 词库时 `vocabularySearch` 使用 SQL LIKE 可能变慢。当前不做优化，但预留注释标记"数据量大后可升级 FTS5"。

### 3.2 WordWorkbench 展示空字段

**问题：** 设计文档要求"空字段用虚线边框表示'待补充'"，但当前代码直接 `return null`，用户无法发现还有哪些字段可填。

**方案：** 对有值的字段保持当前样式，对空字段改为展示虚线边框 + "点击添加"文案。

```
无值字段渲染：
  ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
  │ 使用场景              │  (虚线的 border)
  │ 点击添加…             │
  └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘

有值字段保持不变：
  ┌──────────────────┐
  │ 中文释义           │
  │ 实施；执行    📖词典 │  (实线 border)
  └──────────────────┘
```

**视觉细节：**
- 虚线颜色：`#D9D4CE`（与边框一致）
- 点击行为：同有值字段，进入编辑模式
- 来源标签：空字段没有来源标签

### 3.3 移除 FieldSelector 的动态 import

**问题：** `FieldSelector.tsx` 在 `handleSave` 中使用 `await import('../../db/fields')` 来调用 `upsertFieldValue`，但文件顶部已有 `import { getFieldDefinitions } from '../../db/fields'`。不一致。

**方案：** 将 `upsertFieldValue` 的 import 移到文件顶部和其他 import 一起。

## 4. 架构准备

### 4.1 Error Boundary

**问题：** 组件树任何一层抛出未捕获错误都会导致整个应用白屏，且用户无反馈。

**方案：** 新增 `ErrorBoundary` 组件包裹整个路由树。

```
src/components/ui/ErrorBoundary.tsx
  → 类组件（React error boundary 必须是类组件）
  → 捕获后显示友好错误页 + 错误详情（可折叠）
  → "重试"按钮 + "重启应用"指引
```

**ErrorBoundary 的UI：**
- 居中卡片布局
- 品牌色背景的温和错误提示
- 错误信息在可展开区域（避免非技术用户困惑）

**改动范围：**
- 新增 `src/components/ui/ErrorBoundary.tsx`
- `src/App.tsx` — 包裹 `<Routes>`

### 4.2 Service Layer 引入

**动机：** 当前业务逻辑散落在 Zustand store、React 组件、db 层中。v0.2 的多词义和层级字段将大幅增加业务规则，需要干净的承载层。

**原则：**
- Service Layer 是纯 TypeScript 模块，不依赖 React
- 一个 Service 对应一个领域概念
- 当前先建空壳 + 迁移 v0.1 已有的逻辑；v0.2 的新逻辑直接建在 Service 层上

**目录结构：**

```
src/services/
├── wordService.ts       单词相关的业务规则
│   ├── addWord()        创建单词 + 默认字段（当前在 store）
│   ├── deleteWord()     删除单词 + 级联清理
│   └── getPreviews()    批量获取单词预览（从 db 层抽取）
│
├── fieldService.ts      字段相关的业务规则
│   ├── getDefinitions() 字段定义（含缓存）
│   ├── upsertValue()    更新字段值（当前在 store）
│   └── getValues()      获取字段值（当前在 store）
│
└── searchService.ts     搜索相关的业务规则（预留）
    ├── searchVocabulary()   词库内搜索（封装 vocabularySearch）
    └── searchDictionary()   词典搜索（当前在 TopSearchBar）
```

**迁移策略（渐进式、不改组件）：**
1. 先建 `src/services/` 目录和文件
2. 将 `wordStore.ts` 中非状态管理的逻辑（addWord 的去重检查等）移到 service
3. Store 改为调用 Service 而不是直接调 db
4. 组件层感知不到变化

**注意：** 这不是重写。现有代码逻辑复制到 Service 层，Store 变得"薄"一点。不在 v0.1.1 做大规模重构。

#### 4.2.1 为什么不把 Rust 当作 Service Layer

Rust 侧添加业务逻辑需要：写 Rust 代码 → 注册 Command → 前端 invoke → 处理序列化。对于频繁迭代的业务规则来说，这个循环太慢。

Service Layer 在 TypeScript 侧保持快速迭代能力。只有以下情况才下沉到 Rust：

- 敏感操作（API key 管理）
- 重型计算（大词典文件解析）
- 文件系统操作（导入/导出）

这些在 v0.1.1 都不涉及。

## 5. UI 打磨 — "丝滑的纸质感工坊"

### 5.1 设计 Token 系统

**当前问题：** 品牌色值硬编码在 14 个文件中。不一致、难以维护。

**方案：** 在全局 CSS 中定义 Token 变量（同时用于 Tailwind v4 的 `@theme` 指令）。

```css
:root {
  /* 01. 色彩系统 - 温暖的中性色 */
  --color-canvas: #F6F4EF;        /* 亚麻画布：主背景 */
  --color-surface: #FFFFFF;       /* 纸张白：卡片/工作台背景 */
  --color-surface-hover: #FAF9F6; /* 微交互：悬停微泛黄 */

  --color-text-primary: #1C1814;  /* 墨棕：主文字，比纯黑柔和 */
  --color-text-secondary: #7A7368;/* 羊毛灰：辅助信息 */

  --color-brand: #4A6FA5;         /* 靛蓝：品牌色，编织线/强调 */
  --color-accent: #C17A4E;        /* 陶土橙：极少量点缀，搜索高亮 */

  --color-border: #E8E4DE;        /* 织纹灰：边框线，若有若无 */

  /* 02. 交互变量 - 保证丝滑 */
  --ease-out-smooth: cubic-bezier(0.4, 0, 0.2, 1);
  --duration-fast: 150ms;
  --duration-normal: 250ms;
}
```

> **注意：边框色从 v0.1 的 `#D9D4CE` 改为 `#E8E4DE`**（更浅、更柔和，符合"若有若无"的纸质感）。这些 Token 同时被 Tailwind 引用。

**迁移策略：**
1. 在 `src/index.css` 中（或新建 `src/styles/tokens.css`）定义 Token
2. Tailwind v4 中使用 `@theme` 指令引用这些变量（如果 tailwind 配置支持）
3. 逐个文件替换硬编码色值，**包括** 移除所有 `focus:ring-*`（用户规范要求不使用阴影式反馈）
4. 确保现有组件的视觉效果平滑过渡，不突变

### 5.2 排版美学

**问题：** 当前全应用使用系统无衬线体，单词和 UI 文字没有区分，缺乏层次感。

**方案：** 两套字体策略——单词本体用衬线体，UI 用无衬线体。

```css
:root {
  /* 单词本体：衬线体，书卷气 */
  --font-word: 'Georgia', 'Times New Roman', serif;
  /* UI 文字：系统无衬线体 */
  --font-ui: -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
  /* 行高：增加呼吸感 */
  --line-height-relaxed: 1.6;
}
```

**应用规则：**

| 位置 | 字体 | 字号 | 行高 |
|------|------|------|------|
| 单词标题（工作台顶部） | `--font-word` | 24px+ | 1.4 |
| 词库列表的单词名 | `--font-word` | 16px | 1.4 |
| UI 标签/按钮/输入 | `--font-ui` | 14px | 1.6 |
| 辅助信息（释义、词性预览） | `--font-ui` | 13px | 1.6 |
| 搜索框/小提示 | `--font-ui` | 14px | 1.6 |

**改动范围：**
- 在 `tokens.css` 中添加字体变量
- 为 `.word-heading`、`.word-lemma` 等 CSS class 设置 `font-family`
- 修改 `index.css` 的 `body` 字体为 `--font-ui`

### 5.3 组件视觉规范

#### 5.3.1 词库列表（WordList + WordCard）

设计理念：像一排整齐挂在墙上的工具。

**WordCard 交互状态：**

| 状态 | 背景 | 左侧线 | 额外效果 |
|------|------|--------|---------|
| 默认 | 透明 | `3px` 宽，`--color-border` 色 | — |
| 悬停 | `--color-surface-hover` | 不变 | `transform: translateX(2px)`（GPU 加速），右侧 `→` 箭头 `opacity: 0.5` |
| 选中 | `--color-surface` (纯白) | 变为 `4px` 宽，`--color-brand` 色 | 右侧 `→` 箭头 `opacity: 1` |
| 编织线激活 | — | `--color-brand` 色（当用户添加了自定义内容） | — |

**选中态箭头指示器：**
```
┌─────────────────────────────────┐
│ ▌ implement             →       │  ← opacity 控制显隐
│   实施；执行 · verb             │
└─────────────────────────────────┘
```
箭头用 `→` 字符或 SVG，通过 `opacity` 过渡控制显隐——`opacity` 是 GPU 加速属性，不触发重排。

**性能注意事项：**
- hover 只变 `background-color` 和 `transform`——均为 GPU 加速属性
- 不用 `box-shadow`，不用缩放的 `scale` 动画
- 线宽变化用 `transition: width 150ms ease` 或直接切 class，不用 JS 驱动

**改动范围：**
- `WordCard.tsx` — 添加 `translateX(2px)` hover 动画、右侧箭头元素、线宽从 3px 到 4px 的过渡
- `WordList.tsx` — 不变布局，只传 preview 数据（已在 2.2 节处理）

#### 5.3.2 单词工作台（WordWorkbench）

设计理念：一张平铺的白纸，静待书写。

**容器：**
- 背景 `--color-surface`（纯白）
- 无 `box-shadow`——用 `1px solid var(--color-border)` 界定区域
- 如果工作台自成容器（而非和 IndexPage 背景融为一体），确认布局中已有边框

**字段视觉分级（关键设计）：**

| 数据来源 | 背景 | 文字色 | 边框 | 视觉意图 |
|---------|------|--------|------|---------|
| 词典数据 | `--color-canvas` | `--color-text-secondary` | 实线 `--color-border` | 视觉上"退后"，作为背景参考 |
| 用户数据 | `--color-surface` | `--color-text-primary` | 实线 `--color-brand`（用户聚焦） | 视觉上"突出"，吸引用户聚焦 |
| 空字段 | `--color-surface` | `--color-text-secondary`（占位文字） | 虚线 `--color-border` | 待补充状态 |

**输入交互：**
- **空字段**：虚线边框 `dashed var(--color-border)`，占位文字"点击添加…"
- **聚焦**：边框从虚线变为实线，颜色变为 `--color-brand`，同时 `transform: scale(1.005)`（极其微妙地放大）
  - 性能保证：`transform` 是 GPU 加速的
- **失焦**：如果有值，变为用户数据样式；如果仍为空，恢复虚线边框

**字段容器结构（伪代码）：**
```
<div class="field-block">                    ← 统一间距
  <label class="field-label">中文释义</label>  ← --font-ui, --color-text-secondary
  <div class="field-value" data-source="cc-cedict">  ← 根据来源切换背景色
    实施；执行                ← 词典数据为 --color-canvas 背景
    <span class="source-tag">📖 词典</span>
  </div>
</div>
```

> **注意：** 当前 WordWorkbench 对有值字段的渲染已基本符合要求，主要改动是：词典来源背景色替换、空字段从 `return null` 改为渲染虚线框、聚焦动画添加。

#### 5.3.3 搜索系统（TopSearchBar + DictSearchResult）

**TopSearchBar：**
- 输入框保持现有圆角样式
- 聚焦态：移除 `focus:ring`（无阴影），边框色变为 `--color-brand`

**DictSearchResult（搜索结果下拉框）：**

**改动范围：**

### 5.4 动效系统

**原则：** 所有动效只使用 `transform` 和 `opacity`——GPU 加速属性，不触发重排（reflow）或重绘（repaint）。

**动效清单：**

| 触发时机 | 动效 | 时长 | 缓动 | 作用对象 |
|---------|------|------|------|---------|
| 列表项悬停 | `translateX(2px)` | 150ms | `ease-out-smooth` | WordCard |
| 列表项选中 | 左侧线宽 3px→4px + 颜色变蓝 | 200ms | `ease-out-smooth` | WordCard 左侧线 |
| 选中箭头显隐 | `opacity: 0 ↔ 1` | 150ms | `ease-out-smooth` | WordCard 右侧 `→` |
| 输入框聚焦 | `scale(1.005)` + 边框变色 | 150ms | `ease-out-smooth` | WordWorkbench 字段 |
| 编织线保存确认 | 脉冲动画：变粗→回弹 | 500ms | — | WordCard 左侧线 |
| 页面/单词切换 | `opacity: 0 → 1` 淡入 | 100ms | `ease-out-smooth` | WordWorkbench 内容区 |

**编织线脉冲动画细节（`pulse`）：**
```css
@keyframes weave-pulse {
  0%   { transform: scaleX(1); }
  30%  { transform: scaleX(1.5); }   /* 视觉上变粗 */
  70%  { transform: scaleX(1); }
  100% { transform: scaleX(1); }
}
```
当用户保存笔记/字段后，存储操作成功的回调触发此动画。

> 性能保证：`transform` 是 GPU 加速属性，不触发重排。`scaleX` 沿 X 轴放大符合左侧线"变宽"的视觉需求。

### 5.5 性能红线

以下 CSS 属性和模式**禁止使用**，违反可能导致 PR 被拒：

| ❌ 禁止 | 原因 | ✅ 替代方案 |
|---------|------|------------|
| `box-shadow` | 大面积阴影渲染昂贵，尤其在滚动列表时 | `border: 1px solid var(--color-border)` |
| `filter: blur()` | 模糊滤镜是性能杀手 | 不使用模糊效果 |
| 动画 `width/height/margin/padding` | 触发页面重排（reflow），引起卡顿 | 只用 `transform` 和 `opacity` |
| DOM 节点过多（词库超 100 条） | 卡顿，尤其在低配设备上 | 使用虚拟滚动（`react-window` 或 `virtua`） |

**虚拟滚动准备：**
- 当前不实现虚拟滚动（数据量 < 100 条）
